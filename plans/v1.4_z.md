## 2. 🔴 The one blocker: §12.1 does not fit §10.6

§12.1: a differential operator is "an `OperatorApplication` whose canonical operator identity is `differentiate` and whose canonical parameters contain: Target ParameterID, Order UInt32."

§10.6: `OperatorApplication { OperatorRef ArtifactRef; Args []ArtifactRef }` — **no parameters field**.

Two incompatibilities: (a) the canonical parameters `(Target, Order)` have no home in the declared schema; (b) the differentiation target is a `ParameterID`, not an `ArtifactRef`, so it cannot be an element of `Args` either. As written, an agent implementing §12.1 against §10.6 must invent where the target lives — precisely the invention §47 forbids.

**Fix (choose one, pin it):** add `Parameters CanonicalParameters` to `OperatorApplication` (mirroring §10.11's RuleID-bound pattern, with the differential rule's parameter schema pinned in Appendix B); *or* declare the differential operator application as its own named canonical form under the `differentiate` rule. Either way, also pin (F-2 below) the canonical PhysMath-owned operator identity for `differentiate` — which `Operator` artifact does `OperatorRef` name, and is its ID registry closed?
